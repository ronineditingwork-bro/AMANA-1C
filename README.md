# AMANA-1C

Подключение Claude к 1С:Управление торговлей 11 (база Amana) для анализа заказов и подготовки заявок поставщикам.

Работает через стандартный интерфейс OData 1С (`http://192.168.1.10/ut11/odata/standard.odata/`).
Коннектор **только читает** данные: в 1С ничего не создаёт и не меняет.

## Что умеет

| Инструмент | Что делает |
|---|---|
| `check_connection` | Проверяет подключение и какие объекты опубликованы в OData |
| `sales_report` | Продажи по товарам за период (реализации минус возвраты), выгрузка в CSV |
| `customer_orders_summary` | Заказы клиентов за период: суммы, статусы, топ клиентов и товаров |
| `register_balance` | Остатки любого регистра накопления (ТоварыНаСкладах, ЗаказыПоставщикам…) |
| `reorder_suggestion` | Черновик заявок поставщикам с разбивкой по поставщикам, выгрузка в CSV |
| `list_entity_sets`, `describe_entity`, `odata_query` | Произвольные запросы для любых других вопросов |

### Как считается заявка поставщику

```
продаж в день = продано за N дней / N
нужно         = продаж в день × (срок поставки + запас дней) − (в наличии − резерв) − в пути
```

* Поставщик берётся из последнего поступления товара за год.
* «В пути» берётся из остатков регистра `ЗаказыПоставщикам`; какое поле использовано, пишется в ответе.
* Услуги и группы номенклатуры пропускаются.
* По умолчанию: 90 дней продаж, срок поставки 14 дней, запас 30 дней. Всё меняется в запросе.

Файлы CSV сохраняются в папку `exports/` и открываются в Excel двойным кликом.

## Установка (Windows, компьютер в офисной сети)

Компьютер должен видеть сервер 1С: адрес `http://192.168.1.10/ut11` открывается в браузере.

1. **Python 3.12**: скачать с https://www.python.org/downloads/. При установке отметить **«Add python.exe to PATH»**.
2. **Git**: https://git-scm.com/download/win (все настройки по умолчанию).
3. **Claude Code**: в PowerShell выполнить
   ```powershell
   irm https://claude.ai/install.ps1 | iex
   ```
4. Скачать проект и установить зависимости:
   ```powershell
   cd $HOME
   git clone https://github.com/ronineditingwork-bro/AMANA-1C.git
   cd AMANA-1C
   python -m pip install -r requirements.txt
   ```
5. Настройка доступа к 1С:
   ```powershell
   copy .env.example .env
   notepad .env
   ```
   Вписать пароль пользователя OData (`ONEC_PASSWORD=`) и сохранить. Файл `.env` не попадает в git.
6. Проверка:
   ```powershell
   python -m onec_mcp.check
   ```
   Должно появиться `"подключение": "ok"` и список опубликованных объектов.
7. Запуск: в папке `AMANA-1C` выполнить `claude`. При первом запуске разрешить MCP-сервер `1c`.

## Примеры запросов к Claude

* «Проверь подключение к 1С»
* «Сделай заявку поставщикам: продажи за 90 дней, срок поставки 10 дней, запас на месяц»
* «Заявка только по поставщику Grohe, склад Основной»
* «Проанализируй заказы клиентов за сентябрь: кто больше всего заказал, что в статусе к отгрузке»
* «Топ-30 товаров по продажам за квартал, выгрузи в Excel»

## Безопасность

* Для OData используется отдельный пользователь 1С (`odata.user`), только с нужными объектами.
* Пароли хранятся только в локальном `.env`.
* Коннектор выполняет только GET-запросы. Создание заказов поставщикам в 1С — отдельный следующий этап.

## Дистанционное управление (телефон / веб — в разработке)

Отдельная от Claude Code система для доступа к 1С не только с офисного компьютера, но и с
телефона или другого компьютера — без открытия портов на офисном роутере.

**Как устроено.** `local_agent/` — служба на офисном компьютере, которая сама, исходящим
соединением, раз в несколько секунд спрашивает у `cloud_api/` «есть задача?», выполняет её
через 1С (используя тот же код, что и `onec_mcp/`) и присылает результат. Телефон или веб-страница
создают задачи и читают результаты через `cloud_api/` по HTTPS с токеном.

```
Телефон / веб  →  Cloud API (облако)  ←  Local Agent (офисный ПК, сам стучится наружу)  →  1С
```

**Статус.** Первая контрольная точка — команда `GET_ORDERS` («последние N заказов клиентов»),
проверена целиком end-to-end. `CHECK_STOCK` реализована. `CHECK_RECEIPTS` (контроль поступления)
и `CREATE_SUPPLIER_ORDER` (создание заказа поставщику в 1С, требует прав на запись) — ещё
не реализованы, задачи этого типа сейчас просто отвечают, что пока не готовы.

**Запуск для проверки** — см. `cloud_api/README.md`. Хостинг для Cloud API (VPS или бесплатный
облачный сервис) ещё не выбран; пока всё проверяется локально, на `127.0.0.1`.

## Уведомления в Telegram о новых заказах

`local_agent/telegram_notify.py` — отдельная от Cloud API служба на офисном компьютере. Раз в
минуту (настраивается) сама проверяет в 1С, не появились ли заказы клиентов новее последнего
увиденного, и если да — шлёт по каждому сообщение в Telegram. Входящих подключений не требует:
и к 1С, и к Telegram обращается сама, исходящим соединением.

**Настройка:**
1. В Telegram найдите **@BotFather**, отправьте `/newbot`, следуйте подсказкам — получите токен вида `123456:ABC-...`.
2. Напишите своему новому боту любое сообщение (например «привет»), чтобы он вас увидел.
3. Узнайте свой `chat_id`: откройте в браузере
   `https://api.telegram.org/bot<ваш_токен>/getUpdates` и найдите там `"chat":{"id": ...}`.
4. Впишите оба значения в `local_agent/.env` (`TELEGRAM_BOT_TOKEN`, `TELEGRAM_CHAT_ID`).
5. Запустите: `python local_agent/telegram_notify.py`. При первом запуске он ничего не пришлёт
   (чтобы не завалить чат старыми заказами), только запомнит текущий момент. С этого момента
   все новые заказы будут приходить сообщением.

Заказы, уже созданные до запуска, не присылаются — только новые, начиная с момента запуска.

**Чтобы не запускать вручную и не терять уведомления при закрытии окна PowerShell** — поставьте
как задачу Планировщика заданий Windows: работает в фоне, запускается сама при входе в Windows,
сама перезапускается, если упадёт.
```powershell
powershell -ExecutionPolicy Bypass -File scripts\install_telegram_service.ps1
```
Снять: `powershell -ExecutionPolicy Bypass -File scripts\uninstall_telegram_service.ps1`.
Проверить, что работает: `Get-ScheduledTask -TaskName "AMANA-1C Telegram Notify" | Get-ScheduledTaskInfo`
(`LastTaskResult` `0` или `267009` — оба значат «работает без ошибок»; `267009` означает «задача
выполняется прямо сейчас», это ожидаемо для программы, которая не завершается).

**Требует запуска от имени администратора** — иначе `Register-ScheduledTask` откажет в доступе.

Если `python` у вас разрешается в заглушку Microsoft Store
(`...\AppData\Local\Microsoft\WindowsApps\python.exe` — проверить: `(Get-Command python).Source`),
скрипт сам найдёт настоящий `python.exe` в `%LOCALAPPDATA%\Python`. Если не найдёт — укажите путь
явно: `... -File scripts\install_telegram_service.ps1 -PythonExe C:\путь\к\python.exe`.

**Осторожно:** `copy X.example X.env` перезаписывает файл без предупреждения, даже если он уже
заполнен. Прежде чем копировать образец поверх существующего `.env`, откройте файл и убедитесь,
что в нём ещё нет ваших настроек — иначе придётся заполнять заново.

## Несколько магазинов (разные базы 1С)

Каждый магазин со своей базой 1С получает свою собственную папку `local_agent/stores/<имя>/`
со своим `.env` (свой адрес 1С, свой Telegram-токен или тот же общий), своим состоянием и логом —
магазины работают полностью независимо друг от друга, даже если запущены на одном компьютере.

1. Создайте папку и настройки:
   ```powershell
   copy local_agent\stores\aerodromnaya\.env.example local_agent\stores\aerodromnaya\.env
   notepad local_agent\stores\aerodromnaya\.env
   ```
   (для второго магазина — так же, в папке `local_agent\stores\babushkina\`).
2. Впишите `ONEC_ODATA_URL`/`ONEC_USER`/`ONEC_PASSWORD` для базы этого магазина и `STORE_NAME`
   (попадёт в текст сообщения). Токен и chat_id Telegram можно сделать свои на каждый магазин,
   а можно один общий на оба — тогда уведомления будут в одном чате, с пометкой «Магазин: ...».
3. Проверка вручную: `python local_agent\telegram_notify.py aerodromnaya` (вместо `aerodromnaya` —
   имя папки). Для постоянной работы в фоне — служба, как для одного магазина, но с параметром
   `-Store` (от имени администратора):
   ```powershell
   powershell -ExecutionPolicy Bypass -File scripts\install_telegram_service.ps1 -Store aerodromnaya -PythonExe C:\путь\к\python.exe
   ```
   Снять: `... -File scripts\uninstall_telegram_service.ps1 -Store aerodromnaya`.
   Для второго магазина — то же самое с `babushkina`. Получатся две отдельные службы в
   Планировщике заданий («AMANA-1C Telegram Notify - aerodromnaya» и «... - babushkina»),
   независимые друг от друга.

Запуск `python local_agent\telegram_notify.py` **без** имени магазина — старое поведение (для
одного магазина), использует общие `local_agent/.env` и `local_agent/notify_state.json` напрямую.
